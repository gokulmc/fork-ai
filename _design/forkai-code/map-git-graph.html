Git-graph map — vertical columns

Commits flow DOWN a vertical column (1 git branch = 1 column). Forking a branch (BRANCH) allocates a new column immediately to the right, at the SAME ROW as the commit it forked from — a strict horizontal arrow makes the fork point unambiguous. Learn nodes (go deeper / ask AI) hang BELOW their anchor in a side lane offset to the right, growing downward — never to the side of the trunk. A MERGE ("PR") node rides the TARGET column like any other commit, pulled down to align with its source branch's row, with a straight violet edge carrying the second-parent link in from the source commit. A long run of imported commits collapses into a single dashed "⋯ N commits" placeholder. Node positions below are computed live by the column-allocator in this page's script — its rules are the spec for layoutGitGraph.ts.
